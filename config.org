* Package Management
:PROPERTIES:
:header-args: :tangle yes
:END:

This section establishes the package management infrastructure for Emacs. A reliable and declarative package manager ensures that all external libraries, themes, and language modes are automatically resolved, downloaded, and configured cleanly across different environments.

** Package Archives & MELPA

Emacs includes ~package.el~ as its standard package management client. By default, Emacs connects to GNU ELPA (and NonGNU ELPA in modern Emacs versions). To access the broader community ecosystem of Emacs packages, we register *Milkypostman's Emacs Lisp Package Archive* (MELPA).

- *Homepage*: [[https://melpa.org/][MELPA Official Site]]
- *Repository*: [[https://github.com/melpa/melpa][melpa/melpa on GitHub]]

#+begin_src emacs-lisp
  ;;; config.el --- Emacs configuration -*- lexical-binding: t -*-

  (require 'package)

  ;; Repository configuration - adding MELPA
  (add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)

  ;; Initialize and activate installed packages into load-path
  (package-initialize)
#+end_src

** Declarative Configuration with use-package

~use-package~ provides a macro-based Domain-Specific Language (DSL) for declaring package configurations. It simplifies management by:
- Organizing package initialization (~:init~), configuration (~:config~), and keybindings (~:bind~).
- Enabling deferred (lazy) loading to optimize startup time.
- Handling conditional loading based on system types or installed tools.

Starting with Emacs 29.1, ~use-package~ is built directly into GNU Emacs core, so there is no need to install it from external repositories.

- *Upstream Repository*: [[https://github.com/jwiegley/use-package][jwiegley/use-package on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/use-package.html][use-package on MELPA]]
- *Manual*: [[https://www.gnu.org/software/emacs/manual/html_mono/use-package.html][GNU Emacs use-package Manual]]

#+begin_src emacs-lisp
  ;; Initialize built-in use-package (Emacs 29+)
  (require 'use-package)
#+end_src

** Automatic Package Installation

By default, ~use-package~ requires an explicit ~:ensure t~ directive on each block to trigger automatic package downloads. Setting ~use-package-always-ensure~ to ~t~ globally inverts this default so that any declared package is automatically installed from configured archives unless marked with ~:ensure nil~ (which we reserve for built-in Emacs features like ~dired~ or ~savehist~).

This makes bootstrapping this configuration on a fresh computer completely automatic.

#+begin_src emacs-lisp
  ;; Global setting ensuring that (use-package package-name) 
  ;; automatically downloads and installs it without needing ":ensure t" in every block.
  (setq use-package-always-ensure t)
#+end_src

** General Settings

Baseline configurations to improve everyday editing ergonomics, buffer synchronization, and session state.

*** Custom File & Local Private Configurations

By default, Emacs writes settings modified via the interactive Custom interface (~M-x customize~) directly to the bottom of ~init.el~. To prevent automatically generated Lisp from cluttering version-controlled configuration files, we redirect ~custom-file~ to a separate, untracked ~emacs-custom.el~.

Similarly, we dynamically load ~private.el~ if present. This allows storing private email credentials, local server paths, and machine-specific variables without exposing them to public version control.

#+begin_src emacs-lisp
  (setq custom-file (expand-file-name "emacs-custom.el" user-emacs-directory))
  (when (file-exists-p custom-file)
    (load custom-file))

  (let ((private-file (expand-file-name "private.el" user-emacs-directory)))
    (when (file-exists-p private-file)
      (load private-file)))
#+end_src

*** Modern Prompts (y/n)

Replaces full "yes or no" prompts with single-keystroke "y or n" confirmations. In modern Emacs (version 28+), ~use-short-answers~ is the native, standardized variable that replaces the legacy ~fset 'yes-or-no-p 'y-or-n-p~ alias.

#+begin_src emacs-lisp
  (setq use-short-answers t)
#+end_src

*** Parenthesis Highlighting & Auto-Closing

Efficient Lisp and text editing requires instant visual feedback on delimiter pairs.

- ~show-paren-mode~: Built-in mode that highlights the matching delimiter when the cursor is adjacent to an opening or closing parenthesis, bracket, or brace. Setting ~show-paren-style~ to ~'mixed~ highlights the matching paren if it is visible on screen, or highlights the entire enclosing expression if the matching delimiter is offscreen.
- ~electric-pair-mode~: Built-in minor mode that automatically inserts the matching closing delimiter (parentheses, quotes, brackets) whenever an opening delimiter is typed.

#+begin_src emacs-lisp
  ;; Highlight matching parentheses
  (setq show-paren-style 'mixed)
  (show-paren-mode 1)

  ;; Automatically insert closing delimiters
  (electric-pair-mode 1)
#+end_src

*** Spell Checking with Aspell

Configures Emacs' built-in ~ispell~ interface to use GNU Aspell as the underlying spell-checking engine instead of legacy Ispell. The default dictionary is set to American English.

- *Aspell Homepage*: [[http://aspell.net/][GNU Aspell]]

#+begin_src emacs-lisp
  (setq-default ispell-program-name "aspell")
  (setq ispell-dictionary "american")
#+end_src

*** Automatic Buffer Reversion

When editing files that are concurrently modified by external programs (such as Git checkouts, build scripts, or LaTeX compilers like ~latexmk~), ~global-auto-revert-mode~ ensures that open buffers update automatically when their disk contents change.

- ~global-auto-revert-non-file-buffers~: Extends auto-reversion to buffers that are not directly visiting files, such as Dired directory listings.
- ~auto-revert-verbose nil~: Silences notifications in the echo area so Emacs does not display an annoying message each time a background buffer refreshes.

#+begin_src emacs-lisp
  (global-auto-revert-mode t)
  (setq global-auto-revert-non-file-buffers t)
  ;; Suppress minibuffer notifications on every buffer refresh
  (setq auto-revert-verbose nil)
#+end_src

*** Interactive Configuration Shortcuts

Quick helper functions to reload or open the configuration without having to manually navigate the filesystem:

- ~reload-init~: Re-tangles ~config.org~ into ~config.el~ and evaluates the new configuration immediately.
- ~show-init-file~: Opens ~config.org~ directly in a buffer for fast editing.

#+begin_src emacs-lisp
  (defun reload-init ()
    "Update and reload configuration from the config.org file."
    (interactive)
    (package-initialize)
    (let ((org-file (expand-file-name "config.org" user-emacs-directory))
          (el-file (expand-file-name "config.el" user-emacs-directory)))
      (require 'org)
      (org-babel-tangle-file org-file el-file "\\`\\(?:e\\(?:\\(?:macs-\\)?lisp\\)\\)\\'")
      (let ((tangled-source (concat (file-name-sans-extension (file-truename org-file)) ".el")))
        (when (and (file-exists-p tangled-source)
                   (not (string= (file-truename el-file) (file-truename tangled-source))))
          (copy-file tangled-source el-file t)))
      (load-file el-file)
      (message "Configuration reloaded successfully!")))

  (defun show-init-file ()
    "Open the configuration file for editing."
    (interactive)
    (find-file (expand-file-name "config.org" user-emacs-directory)))
#+end_src

*** Window Scrolling Behavior

Customizes the ~recenter-top-bottom~ command (bound to ~C-l~). By default, successive presses of ~C-l~ cycle the cursor position between the middle, top, and bottom of the active window. Setting ~recenter-positions~ to ~'(top middle bottom)~ prioritizes positioning the cursor near the top on the first invocation.

#+begin_src emacs-lisp
  (setq recenter-positions '(top middle bottom))
#+end_src

*** Asynchronous Backups & Auto-Save on Focus Loss

To prevent data loss without causing editor stutter on large files, we use ~async-backup~. It runs file backup operations in a separate asynchronous process so saving never blocks Emacs.

Additionally, an auto-save hook on ~focus-out-hook~ automatically saves modified buffers whenever the Emacs window loses OS focus (e.g., when switching to a browser or PDF reader).

- *Repository*: [[https://codeberg.org/contrapunctus/async-backup][contrapunctus/async-backup on Codeberg]]
- *MELPA Page*: [[https://melpa.org/packages/async-backup.html][async-backup on MELPA]]

#+begin_src emacs-lisp
  (use-package async-backup
    :hook (after-save . async-backup))

  ;; Autosave all modified buffers when Emacs loses focus
  (add-hook 'focus-out-hook (lambda () (save-some-buffers t)))
#+end_src

- ~global-visual-line-mode~: Enables soft word wrapping at whitespace boundaries rather than truncating long lines or splitting words across rows.
- ~outline-minor-mode~: Enables heading folding and structural navigation in plain text buffers.

#+begin_src emacs-lisp

*** Native Tab Bar & Window Configuration History

Emacs 27+ includes a native tab bar system (~tab-bar-mode~), where each tab represents a distinct window layout (comparable to workspaces or virtual desktops in other editors).

- ~tab-bar-history-mode~: Tracks the history of window configurations within each tab, allowing seamless undo and redo of window layout changes (splits, closures, and resizes) via ~M-[~ and ~M-]~.

** Global Keybindings & Platform Tweaks

*** macOS Modifier Keys

When running GNU Emacs on macOS (Darwin/NextStep), the default modifier key mappings can conflict with standard macOS desktop conventions. This configuration maps:
- *Left Option*: mapped to ~alt~ (used for window navigation with windmove).
- *Right Option*: left unassigned (~none~) to permit entering special Polish diacritics / symbols via standard macOS keyboard layout.
- *Left Command*: mapped to ~meta~ (providing ergonomic ~M-~ access using the thumb).
- *Right Command*: mapped to ~super~ (~s-~).

#+begin_src emacs-lisp
  (when (eq system-type 'darwin)
    (setq ns-option-modifier 'alt
          ns-right-option-modifier 'none
          ns-command-modifier 'meta          ;; Left Command is Meta (M-)
          ns-right-command-modifier 'super)) ;; Right Command is Super (s-)
#+end_src

*** Global Text Scaling

Quick global keybindings to zoom buffer text in or out interactively.

#+end_src

** Background Emacs Server

Starting the built-in Emacs server allows external terminal commands (~emacsclient~) to quickly open files inside the existing Emacs instance without starting a new process.

Crucially, running the server is required for *SyncTeX backward-search* in PDF viewers (such as PDF-Tools or macOS Skim), allowing clicking on a location in a compiled PDF to jump directly to the corresponding source line in the LaTeX buffer.

- *Manual*: [[https://www.gnu.org/software/emacs/manual/html_node/emacs/Emacs-Server.html][GNU Emacs Server Manual]]

#+begin_src emacs-lisp
  (use-package server
    :ensure nil ; Built into Emacs
    :config
    (unless (server-running-p)
      (server-start)))
#+end_src

*** Automatic Window Sizing with zoom

~zoom~ dynamically resizes the currently active window to give it optimal visual focus while shrinking inactive windows. Unlike the unmaintained legacy ~golden-ratio~ package, ~zoom~ handles modern window layouts, child frames, and popups cleanly without visual glitches or jitter.

Here, we configure ~zoom~ to scale the active window according to the golden ratio (~0.618~), while ignoring specific debugging, diffing, and REPL modes where automatic resizing would disrupt the interface.

- *Repository*: [[https://github.com/cyrus-and/zoom][cyrus-and/zoom on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/zoom.html][zoom on MELPA]]

#+begin_src emacs-lisp
  (use-package zoom
    :custom
    ;; Scale active window according to the golden ratio
    (zoom-size '(0.618 . 0.618))
    (zoom-ignored-major-modes '(ediff-mode
                                helm-mode
                                gud-mode
                                gdb-locals-mode
                                gdb-registers-mode
                                gdb-breakpoints-mode
                                gdb-threads-mode
                                gdb-frames-mode
                                gdb-inferior-io-mode
                                gdb-disassembly-mode
                                gdb-memory-mode
                                ielm-mode))
    :config
    (zoom-mode 1))
#+end_src

*** Editing Utilities with crux

~crux~ (Collection of Ridiculously Useful eXtensions) provides essential text editing commands created by Bozhidar Batsov:
- ~crux-cleanup-buffer-or-region~: Cleans trailing whitespace and untabifies in one keystroke.
- ~crux-duplicate-current-line-or-region~: Duplicates lines without having to select and copy them.
- ~crux-move-beginning-of-line~: Moves cursor to the first non-whitespace character on first press, and to the beginning of the line on second press.

*** Moving Lines & Selected Regions with drag-stuff

~drag-stuff~ provides an intuitive way to drag lines, words, or selected active regions up and down while automatically maintaining proper syntax indentation. It is particularly effective for rearranging items in LaTeX lists, mathematical calculation steps, or reordering code statements without having to kill and yank.

- ~M-<up>~ (~drag-stuff-up~): Moves the current line or active region up by one line.
- ~M-<down>~ (~drag-stuff-down~): Moves the current line or active region down by one line.
- Org-mode exclusion: To prevent overriding Org-mode's native hierarchical subtree and item manipulation commands (~org-metaup~ / ~org-metadown~), ~org-mode~ is explicitly added to ~drag-stuff-except-modes~.

- *Repository*: [[https://github.com/rejeep/drag-stuff.el][rejeep/drag-stuff.el on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/drag-stuff.html][drag-stuff on MELPA]]

#+begin_src emacs-lisp
  (use-package drag-stuff
    :bind (("M-<up>"   . drag-stuff-up)
           ("M-<down>" . drag-stuff-down))
    :config
    (drag-stuff-global-mode 1)
    ;; Exclude Org mode so native org-metaup and org-metadown remain unhindered
    (add-to-list 'drag-stuff-except-modes 'org-mode))
#+end_src

** Shell Environment Synchronization (exec-path-from-shell)

On macOS, graphical GUI applications launched from the Finder or Dock do not run inside an interactive login shell. Consequently, Emacs does not inherit shell environment variables such as ~$PATH~, ~$MANPATH~, or Homebrew paths (~/opt/homebrew/bin~).

~exec-path-from-shell~ queries the user's default shell (e.g., Zsh) upon startup and copies the environment variables into Emacs, ensuring external tools (compilers, git, python, ripgrep) are found seamlessly.

- *Repository*: [[https://github.com/purcell/exec-path-from-shell][purcell/exec-path-from-shell on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/exec-path-from-shell.html][exec-path-from-shell on MELPA]]

#+begin_src emacs-lisp
  (use-package exec-path-from-shell
    :config
    (when (or (memq window-system '(mac ns x))
              (daemonp))
      (exec-path-from-shell-initialize)))
#+end_src

** Undo Management

*** Visual Undo Tree with vundo

Emacs possesses a powerful undo system that never loses history, but navigating complex undo branches linearly can be confusing. ~vundo~ displays the undo tree as an interactive visual graph using Unicode characters, allowing intuitive spatial traversal through editing history without modifying the native undo data structures.

- *Repository*: [[https://github.com/casouri/vundo][casouri/vundo on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/vundo.html][vundo on MELPA]]

#+begin_src emacs-lisp
  (use-package vundo
    :bind ("C-x u" . vundo)
    :config
    ;; Use prettier Unicode characters for the tree lines
    (setq vundo-glyph-alist vundo-unicode-symbols))
#+end_src

*** Native Linear Undo & Redo

Emacs 28+ natively includes explicit ~undo-only~ and ~undo-redo~ commands, eliminating the need for external wrapper packages like ~undo-fu~.

- ~undo-only~ (~C-/~): Strictly reverses previous edits in a linear fashion without reversing direction into redo.
- ~undo-redo~ (~C-?~): Redoes changes that were just undone, matching the standard redo behavior found in modern editors.
- When paired with ~vundo~ (~C-x u~), you get both simple linear undo/redo and the ability to visually branch into arbitrary points in history without any risk of corruption.

#+begin_src emacs-lisp
  ;; Native linear undo and redo (built into Emacs 28+)
  (global-set-key (kbd "C-/") 'undo-only)
  (global-set-key (kbd "C-?") 'undo-redo)
#+end_src

* Hydra
:PROPERTIES:
:header-args: :tangle yes
:END:

Emacs commands often require multi-key sequences (such as ~C-x o~ or ~C-c w~). When performing repetitive actions—such as rearranging split windows, navigating tabs, tweaking keyboard macros, or querying documentation—re-typing prefix keys over and over introduces friction.

~hydra~ solves this by creating transient keybinding states that "stick around". Once a Hydra body is invoked, related actions can be executed repeatedly with single keystrokes until you explicitly dismiss the state.

- *Repository*: [[https://github.com/abo-abo/hydra][abo-abo/hydra on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/hydra.html][hydra on MELPA]]

Hydra defines different execution semantics via color heads:
- **red** (default): Executes the command and keeps the Hydra active.
- **blue**: Executes the command and immediately exits the Hydra.
- **amaranth**: Executes the command and intercepts non-Hydra keys (preventing accidental exits until an explicit exit key is pressed).
- **pink**: Executes the command and allows non-Hydra keys to run normally while exiting the Hydra.
- **teal**: Like blue, but foreign keys are blocked.

** Core Setup & Global Entry Points

Initializes ~hydra~ and defines convenient global entry shortcuts for the most frequently used operational workflows.

** Interactive Hydra Inspector (my/list-config-hydras)

An interactive diagnostic utility that dynamically scans your Emacs configuration for all defined Hydras and extracts their global keybindings (from ~:bind~ declarations, ~global-set-key~, or ~keymap-global-set~), presenting them in a dedicated ~*My Hydras*~ inspection buffer.

Also accessible from the quick-navigator buttons on the startup Dashboard.

#+begin_src emacs-lisp
  (defun my/list-config-hydras ()
    "Scan configuration for defined Hydras and their global keybindings."
    (interactive)
    (let* ((config-path (expand-file-name "config.el" user-emacs-directory))
           (org-path (expand-file-name "config.org" user-emacs-directory))
           (target-file (cond ((file-exists-p config-path) config-path)
                              ((file-exists-p org-path) org-path)
                              (t nil)))
           (hydra-list '()))
      (if (not target-file)
          (message "Neither config.el nor config.org found in %s" user-emacs-directory)
        (with-temp-buffer
          (insert-file-contents target-file)
          (goto-char (point-min))
          ;; Regexp to find (defhydra hydra-name ...) at the start of a line
          (while (re-search-forward (concat "^[ \t]*(\\(?:def\\)" "hydra[ \t\n]+\\([a-zA-Z0-9/-]+\\)") nil t)
            (let* ((name (match-string 1))
                   (binding "No global binding found"))
              (save-excursion
                (goto-char (point-min))
                ;; Match :bind (("KEY" . hydra-.../body)), global-set-key, or keymap-global-set
                (if (or (re-search-forward (format "\"\\([^\"]+\\)\"[ \t]*\\.[ \t]*%s/body" (regexp-quote name)) nil t)
                        (re-search-forward (format "kbd[ \t]+\"\\([^\"]+\\)\"[ \t)]+.*%s/body" (regexp-quote name)) nil t)
                        (re-search-forward (format "keymap-global-set[ \t]+\"\\([^\"]+\\)\"[ \t]+.*%s/body" (regexp-quote name)) nil t))
                    (setq binding (match-string 1))))
              (push (cons name binding) hydra-list))))

        ;; Display the results
        (if (null hydra-list)
            (message "No Hydras found in configuration")
          (with-output-to-temp-buffer "*My Hydras*"
            (princ "Defined Hydras in Configuration:\n")
            (princ "================================\n\n")
            (dolist (hydra (reverse hydra-list))
              (princ (format "%-25s Key: %s\n" (car hydra) (cdr hydra)))))))))
#+end_src

* PDF-Tools
:PROPERTIES:
:header-args: :tangle yes
:END:

By default, Emacs views PDF documents using ~doc-view-mode~, which relies on external utilities (ImageMagick or Ghostscript) to convert pages into rasterized PNG images. This approach is slow, blurry on high-DPI (Retina) displays, and lacks native text selection or fine-grained navigation.

~pdf-tools~ completely replaces ~doc-view-mode~ with an in-buffer vector renderer driven by Poppler via a native server binary (~epdfinfo~). It provides:
- Crisp vector rendering at any zoom level with sub-pixel antialiasing.
- Native text selection, search, copying, and in-buffer highlighting/annotations.
- Direct bidirectional SyncTeX integration with LaTeX (clicking a location in the PDF jumps directly to the source code line in AUCTeX, and vice versa).
- Fast in-document text search.

- *Repository*: [[https://github.com/vedang/pdf-tools][vedang/pdf-tools on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/pdf-tools.html][pdf-tools on MELPA]]
- *Prerequisites*: Requires Poppler installed on your system. On macOS with Homebrew: ~brew install poppler automake autoconf pkg-config~.

** Viewer Setup & Configuration

- ~:mode~ & ~:magic~: Automatically activates ~pdf-view-mode~ for files ending in ~.pdf~ or starting with the standard ~%PDF~ magic byte header. Using ~:mode~ defers package loading until a PDF is actually visited.
- ~(pdf-tools-install :no-query)~: Compiles/initializes the native ~epdfinfo~ server without interactive prompts.
- ~pdf-view-display-size 'fit-page~: Default to fitting the entire page vertically in the window.
- ~C-s~ bound to ~isearch-forward~: Ensures standard Emacs incremental search triggers the PDF text search engine even when global completion frameworks (like Helm or Swiper) are active.
- ~auto-revert-mode~ hook: Automatically reloads the PDF buffer whenever the file is updated on disk (essential when compiling documents with ~latexmk~ or AUCTeX).

#+begin_src emacs-lisp
  (use-package pdf-tools
    :mode ("\\.pdf\\'" . pdf-view-mode)
    :magic ("%PDF" . pdf-view-mode)
    :bind (:map pdf-view-mode-map
           ("C-s"   . isearch-forward)
           ("C-c s" . my/pdf-check-signatures))
    :custom
    (pdf-view-display-size 'fit-page)
    :hook
    ;; Automatically refresh the PDF buffer when recompiled by LaTeX / external tools
    (pdf-view-mode . auto-revert-mode)
    :config
    ;; Initialize the epdfinfo server seamlessly without interactive prompting
    (pdf-tools-install :no-query))
#+end_src

* Dired
:PROPERTIES:
:header-args: :tangle yes
:END:

Dired (Directory Editor) is Emacs' built-in file manager. Rather than acting as a static file browser, it renders filesystem directories as interactive Emacs buffers where you can navigate, flag files for deletion (~d~), rename files interactively with standard cursor movements (~R~), copy (~C~), compress (~Z~), and edit filenames using multi-file search and replace (~wdired-change-to-wdired-mode~ via ~C-x C-q~).

This section configures clean navigation ergonomics, macOS BSD compatibility fixes, inline subdirectory tree expansions, custom diffing, external PDF viewing, and visual grouping.

- *Manual*: [[https://www.gnu.org/software/emacs/manual/html_node/emacs/Dired.html][GNU Emacs Dired Manual]]

** Core Configuration

Essential defaults to streamline file operations and prevent buffer sprawl:

- ~dired-recursive-copies 'always~ & ~dired-recursive-deletes 'always~: Copies and deletes nested directory hierarchies without prompting for confirmation on each file.
- ~dired-dwim-target t~: "Do What I Mean" target detection. When two Dired windows are open side-by-side, pressing ~C~ (copy) or ~R~ (rename/move) automatically guesses the other visible Dired folder as the destination.
- ~dired-kill-when-opening-new-dired-buffer t~: Added in Emacs 28+. Reuses the current buffer when descending into subdirectories instead of spawning a new buffer for every folder visited.
- ~dired-listing-switches "-agho --group-directories-first"~: Formats listings with hidden files, human-readable sizes, and groups subdirectories at the top.
- ~auto-revert-mode~ hook: Keeps Dired buffers in sync with external filesystem modifications.

*** macOS BSD Compatibility (ls-lisp)

On macOS, the native BSD system ~/bin/ls~ utility does not support the GNU ~--group-directories-first~ flag, causing Dired to fail on startup. 

By setting ~ls-lisp-use-insert-directory-program nil~ and loading ~ls-lisp~, Emacs uses its built-in pure Lisp file listing engine. This guarantees full cross-platform compatibility without requiring external Homebrew coreutils (~gls~).

#+begin_src emacs-lisp
  (use-package dired
    :ensure nil ; Built into Emacs
    :custom
    (dired-recursive-copies 'always)
    (dired-recursive-deletes 'always)
    (dired-listing-switches "-agho --group-directories-first")
    (dired-dwim-target t)
    ;; Reuse the current buffer when navigating into subdirectories (Emacs 28+)
    (dired-kill-when-opening-new-dired-buffer t)
    :hook
    (dired-mode . auto-revert-mode)
    :bind (:map dired-mode-map
           ("e" . my/ediff-files-in-dired)
           ("V" . my/dired-open-pdf-in-preview))
    :config
    ;; Fix for macOS: use Emacs' internal Lisp implementation of ls
    ;; to support --group-directories-first without external GNU coreutils
    (setq ls-lisp-use-insert-directory-program nil)
    (require 'ls-lisp))
#+end_src

* Terminal Emulators
:PROPERTIES:
:header-args: :tangle yes
:END:

Emacs provides multiple ways to interact with command-line tools. This section configures two complementary terminal solutions:

1. **Eshell**: A portable, pure-Elisp command shell deeply integrated with Emacs Lisp and remote TRAMP buffers.
2. **Vterm**: A lightning-fast, full-featured terminal emulator based on the native C library ~libvterm~, capable of running complex terminal applications (~htop~, ~lazygit~, ~tmux~, interactive REPLs) at native speeds.
3. **Vterm Toggle**: A Quake-style drop-down terminal drawer pinned to the bottom of the screen, bound to ~C-t~.

** Eshell (Emacs Lisp Shell)

~eshell~ is implemented entirely in Emacs Lisp, making it completely uniform across operating systems without requiring an external shell binary. It can evaluate Elisp functions inline, pipe program output directly into Lisp variables or Emacs buffers, and seamlessly traverse remote servers via TRAMP.

- ~company-mode~ hook: Enables in-buffer autocomplete for file paths, commands, and arguments.
- ~eshell-history-size 10000~: Extends the command history retention.
- ~eshell-destroy-buffer-when-process-dies t~: Automatically closes the Eshell buffer when typing ~exit~.

- *Manual*: [[https://www.gnu.org/software/emacs/manual/html_node/eshell/][GNU Emacs Eshell Manual]]

** Vterm (libvterm Terminal Emulator)

~vterm~ (emacs-libvterm) is an ultra-fast terminal emulator implemented as a dynamic C module linked against ~libvterm~. Unlike Emacs' legacy ~ansi-term~ or ~term~ modes, ~vterm~ can render high-throughput text streams, full ANSI 24-bit RGB colors, and interactive curses programs without UI stutter or memory bottlenecks.

- *Repository*: [[https://github.com/akermu/emacs-libvterm][akermu/emacs-libvterm on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/vterm.html][vterm on MELPA]]
- *Prerequisites*: Requires ~cmake~ and ~libvterm~. On macOS with Homebrew: ~brew install cmake libvterm~.

*Keybindings & Modes:*
- Standard keystrokes are passed directly to the shell process.
- ~C-c C-t~ (~vterm-copy-mode~): Toggles copy mode, freezing the terminal into a standard readable Emacs buffer where you can navigate, search (~C-s~), and copy text using standard Emacs marks.
- ~C-c C-y~: Pastes text into the terminal from the Emacs kill ring.

* Modern Completion (Replacement for Helm)
:PROPERTIES:
:header-args: :tangle yes
:END:

Historically, monolithic frameworks like Helm and Ivy dominated Emacs interactive completion. While powerful, they reinvented custom completion protocols, introduced heavy runtime overhead, and often bypassed or rewrote Emacs' native completion primitives.

Modern Emacs setups favor the modular **Minad / Vertico ecosystem** (Vertico, Marginalia, Orderless, and Consult). Rather than replacing Emacs' completion engine, these packages strictly build on top of the built-in ~completing-read~ standard API. They are lightweight, blazingly fast, fully composable, and universally compatible with any package using standard Emacs completion.

** Vertico (Vertical Interactive Completion)

~vertico~ transforms the horizontal minibuffer into a vertical list of completion candidates with responsive scrolling and candidate cycling. Because it relies purely on the standard Emacs completion API, it has virtually zero overhead and integrates cleanly with all core commands (~find-file~, ~switch-to-buffer~, ~M-x~).

- *Repository*: [[https://github.com/minad/vertico][minad/vertico on GitHub]]
- *MELPA Page*: [[https://melpa.org/packages/vertico.html][vertico on MELPA]]

#+begin_src emacs-lisp
  (use-package vertico
    :init

    (vertico-mode 1)
    :custom
    ;; Wrap around to the top/bottom when scrolling past the list boundary
    (vertico-cycle t))
#+end_src

** Marginalia (Rich Minibuffer Annotations)

~marginalia~ displays contextual information in the margin alongside completion candidates (such as file permissions, human-readable file sizes, modification timestamps, function docstrings, and variable values).

To avoid timestamp discrepancies and calculation issues on cloud-synced storage (e.g. Google Drive, iCloud, or macOS file shares), we set ~marginalia-max-relative-age 0~ to consistently format dates with absolute timestamps (~YYYY-MM-DD HH:MM~).

- *Repository*: [[https://github.com/minad/marginalia][minad/marginalia on GitHub]]

** Environment & Performance Tuning

High-throughput Language Server Protocol (LSP) communication exchanges voluminous JSON-RPC payloads between external language server processes (such as Pyright, Clangd, or Rust-Analyzer) and Emacs. By default, Emacs reads process output in 4KB chunks and runs garbage collection aggressively (~800KB threshold), which causes noticeable input latency and frame drops during fast code completion and diagnostic checks.

Tuning these low-level IPC and memory settings eliminates stuttering and enables silky-smooth LSP interaction on modern multi-core machines (particularly on macOS Apple Silicon).

Note: Environment variable synchronization (~$PATH~, ~$MANPATH~) across GUI Emacs frames is handled globally by ~exec-path-from-shell~ in the [[*Shell Environment Synchronization (exec-path-from-shell)][Interface Tweaks]] section, eliminating redundant shell subprocess spawns during startup.

#+begin_src emacs-lisp
  ;; Global performance tweaks for LSP/Development
  (defun my/optimize-lsp-performance ()
    "Set key variables for LSP/Eglot stability and performance on macOS."
    (setq read-process-output-max (* 1024 1024)   ; 1MB buffer for reading process outputs (default is 4KB)
          gc-cons-threshold (* 100 1024 1024)))   ; 100MB GC threshold during development to prevent stutter

  (my/optimize-lsp-performance)
#+end_src

*** SageMath Pyright Configuration Generator

SageMath installs extensive Python site-packages inside its Conda or system environment. Because Pyright does not execute external interpreters dynamically, it needs explicit search paths defined in ~pyrightconfig.json~ under ~extraPaths~ to resolve SageMath imports and types.

The interactive function ~my/generate-sage-pyright-config~ sources the user's shell environment, queries Sage's active ~sys.path~, and writes a localized ~pyrightconfig.json~ at the project root before restarting the LSP workspace.

#+begin_src emacs-lisp
  (defun my/generate-sage-pyright-config (env-name)
    "Generates pyrightconfig.json by sourcing .zshrc and running a temp python script.
  ENV-NAME: The name of the conda environment (string)."
    (interactive
     (list
      (read-string "Conda environment name (default sage_env): " nil nil "sage_env")))
    (let* ((project-root (projectile-project-root))
           (config-file (expand-file-name "pyrightconfig.json" project-root))
           (temp-script-file (make-temp-file "sage_paths_" nil ".py")))
      (with-temp-file temp-script-file
        (insert "import sys, json\n")
        (insert "print('__JSON_START__' + json.dumps([p for p in sys.path if 'site-packages' in p]) + '__JSON_END__')"))
      (let* ((shell-cmd (format "zsh -c 'source ~/.zshrc && load_conda && conda activate %s && sage -python %s'" 
                                env-name temp-script-file))
             (raw-output (shell-command-to-string shell-cmd))
             (clean-json (if (string-match "__JSON_START__\\(.*\\)__JSON_END__" raw-output)
                             (match-string 1 raw-output) nil)))
        (delete-file temp-script-file)
        (if (not clean-json)
            (with-current-buffer (get-buffer-create "*sage-config-debug*")
              (erase-buffer)
              (insert (format "ERROR: Could not extract paths from env: %s\n" env-name))
              (insert raw-output)
              (pop-to-buffer (current-buffer))
              (error "Failed. Check *sage-config-debug*."))
          (with-temp-file config-file
            (insert "{\n \"extraPaths\": ")
            (insert clean-json)
            (insert "\n}")
            (indent-region (point-min) (point-max)))
          (message "Success! Configured Pyright for environment: %s" env-name)
          (lsp-workspace-restart)))))
#+end_src

- ~org-directory "~/Dropbox/org"~: Central directory for all personal and academic notes.
- ~org-log-into-drawer t~ and ~org-clock-into-drawer "LOGBOOK"~: Automatically channels state change notes and clocking timestamps into collapsed ~:LOGBOOK:~ drawers, keeping the main note body clean and readable.

*** Dynamic Agenda & Refiling Logic
- ~org-agenda-files~: Automatically scans the entire ~agenda/~ directory recursively for all ~.org~ files when the directory exists on disk.
- ~org-default-notes-file~: Directs new captures to ~~/Dropbox/org/agenda/Inbox.org~.
- Refiling targets (~org-refile-targets~): Allows refiling entries up to 5 levels deep across all active agenda files with full outline path completion (~org-refile-use-outline-path 'file~).
- Task Dependencies (~org-enforce-todo-dependencies t~): Prevents marking a parent or sequential task as DONE until all dependent child tasks are completed, visually dimming blocked tasks in agenda views.

    :ensure t
    :bind
    (("C-c l" . org-store-link)
     ("C-c a" . org-agenda)
     ("C-c c" . org-capture))

           (org-mode . org-indent-mode))
    :config

    (setq org-M-RET-may-split-line '((default . nil))
          org-log-into-drawer t

          org-catch-invisible-edits 'smart
          org-hide-emphasis-markers t)

    ;; Academic/Math focus: highlight LaTeX math, scripts, and entities
    (setq org-highlight-latex-and-related '("latex" "script" "entities"))

    ;; Agenda setup: Automatically discover all .org files in the agenda directory
    (when (file-directory-p org-agenda-directory)
      (setq org-agenda-files (directory-files-recursively org-agenda-directory "\\.org$")))
    (setq org-default-notes-file (concat org-agenda-directory "/Inbox.org"))

    ;; Refiling logic across all agenda files
    (setq org-refile-use-outline-path 'file
          org-outline-path-complete-in-steps nil
          org-refile-targets '((org-agenda-files :maxlevel . 5))
          org-refile-allow-creating-parent-nodes t)

    ;; Task Dependencies
    (setq org-enforce-todo-dependencies t
          org-track-ordered-property-with-tag t
          org-agenda-dim-blocked-tasks t)

    ;; Persist clocking history across Emacs sessions
    (org-clock-persistence-insinuate))

*** Unique ID Link Generation (<f6>)
~my/copy-idlink-to-clipboard~ generates or retrieves a permanent UUID for the current headline (~org-id-get-create~) and places a formatted ~[[id:uuid][Headline]]~ link onto the kill ring. If called from an active Agenda buffer, it seamlessly switches to the underlying file heading first.

            (lambda ()
              (when (member org-state org-done-keywords)
                (org-reset-checkbox-state-maybe))))

  (defun my/copy-idlink-to-clipboard ()
    "Create or get an ID for the current headline and copy a link to clipboard."
    (interactive)
    (when (eq major-mode 'org-agenda-mode)
      (org-agenda-show)
      (org-agenda-goto))

        (let* ((head (nth 4 (org-heading-components)))
               (id (org-id-get-create))

          (message "Copied ID link: %s" link))

* Yasnippet
:PROPERTIES:
:header-args: :tangle yes
:END:

A template expansion system for Emacs that dramatically accelerates coding, document authoring, and repetitive boilerplate entry. By typing a brief mnemonic abbreviation and pressing the expansion key, YASnippet replaces the keyword with a structured template containing tab stops, placeholder defaults, mirrored fields, and embedded Elisp transformations.

** Core Configuration & Snippet Directories

We configure YASnippet to look in our configuration's local ~snippets/~ directory (~user-emacs-directory/snippets~), which houses custom snippets for LaTeX and Org mode. In addition, we load the comprehensive community collection from ~yasnippet-snippets~.

Key settings:
- ~yas-wrap-around-region t~: When a region of text is active, expanding a snippet automatically encloses the highlighted text inside the snippet body (at ~$0~ or the first field) rather than deleting or overwriting it. This enables effortless wrapping of code blocks, HTML/XML tags, or LaTeX environments.
- Selective Mode Hooks: Hooking ~yas-minor-mode~ to ~prog-mode~ and ~text-mode~ ensures snippets are available across all programming buffers, LaTeX, and Org notes while avoiding interference with special read-only or utility buffers (such as Dired, Magit, or Compilation).
- Keybinding: ~C-c C-y~ in ~yas-minor-mode-map~ brings up the dedicated management Hydra.

- *YASnippet Repository*: [[https://github.com/joaotavora/yasnippet][joaotavora/yasnippet on GitHub]]
- *YASnippet MELPA*: [[https://melpa.org/packages/yasnippet.html][yasnippet on MELPA]]
- *Official Documentation*: [[https://joaotavora.github.io/yasnippet/][YASnippet Manual]]
- *Snippet Collection Repository*: [[https://github.com/AndreaCrotti/yasnippet-snippets][AndreaCrotti/yasnippet-snippets on GitHub]]
- *Snippet Collection MELPA*: [[https://melpa.org/packages/yasnippet-snippets.html][yasnippet-snippets on MELPA]]

#+begin_src emacs-lisp
  (use-package yasnippet
    :after hydra
    :hook ((text-mode . yas-minor-mode)
           (prog-mode . yas-minor-mode))
    :bind (:map yas-minor-mode-map
                ("C-c C-y" . hydra-yas/body))
    :config
    ;; Define explicit snippet directory paths
    (setq yas-snippet-dirs
          (list (expand-file-name "snippets" user-emacs-directory)))
    ;; Allow snippets to wrap around selected active regions
    (setq yas-wrap-around-region t)
    ;; Load all snippet definitions
    (yas-reload-all))

  ;; Community-maintained collection of snippets for dozens of languages
  (use-package yasnippet-snippets
    :after yasnippet)

  - ~C-c ! e~: Explain the error under point in detail.

* Flyspell
:PROPERTIES:
:header-args: :tangle yes
:END:

An on-the-fly interactive spell checking environment for prose, academic writing, and programming comments. Flyspell highlights misspelled words in real time and provides rapid in-minibuffer correction interfaces without taking your hands off the keyboard.

** Core Configuration & Bilingual Hunspell Setup

We configure GNU Emacs' built-in ~flyspell~ with [[https://hunspell.github.io/][Hunspell]] as the spell checking engine (installable via Homebrew: ~brew install hunspell~).

Key settings:
- Mode Isolation:
  - ~text-mode-hook~ runs ~flyspell-mode~ (checks every word across Markdown, Org notes, and LaTeX).
  - ~prog-mode-hook~ runs ~flyspell-prog-mode~ (strictly checks comments and docstrings, leaving code identifiers and keywords intact).
- Bilingual Dictionary Switching:
  - Default dictionary set to English (~en_US~).
  - ~ispell-local-dictionary-alist~ defines character boundary rules, UTF-8 encoding, and dictionary flag arguments (~-d~) for both American English (~en_US~) and Polish (~pl_PL~).
- Keybindings:
  - ~C-c f b~: Spellcheck entire buffer (~flyspell-buffer~).
  - ~C-c f d~ / ~C-c f j c~: Select and switch active dictionary (~ispell-change-dictionary~).

#+begin_src emacs-lisp
  (use-package flyspell
    :ensure nil
    :hook ((text-mode . flyspell-mode)
           (prog-mode . flyspell-prog-mode))
    :config
    ;; Use Hunspell as the primary spelling engine
    (setq ispell-program-name "hunspell")

    ;; Default active dictionary
    (setq ispell-dictionary "en_US")

    ;; Dictionary definitions for English and Polish with UTF-8 support
    (setq ispell-local-dictionary-alist
          '(("pl_PL" "[[:alpha:]]" "[^[:alpha:]]" "[']" nil ("-d" "pl_PL") nil utf-8)
            ("en_US" "[[:alpha:]]" "[^[:alpha:]]" "[']" nil ("-d" "en_US") nil utf-8)))

    :bind (:map flyspell-mode-map
                ("C-c f b" . flyspell-buffer)
                ("C-c f d" . ispell-change-dictionary)
                ("C-c f j c" . ispell-change-dictionary)))
#+end_src

** Performance Optimization (flyspell-lazy)

By default, Flyspell executes spell-checking synchronously on every character insertion. In large LaTeX files or dense Org documents, this can introduce noticeable typing delay.

~flyspell-lazy~ solves this by deferring spellcheck operations until Emacs is idle for a brief window, ensuring silky-smooth responsiveness during rapid typing.
